# デフェクトログテンプレート（Defect Log Template）

省略用語（RACI, KPI, ADR, DDL, SLO, QA, PM, TRK, EX）は [../../../shared-references/glossary.md](../../../shared-references/glossary.md) の『略語・日本語対応表』を参照してください。


本テンプレートは、不具合対応全体の監査最小セット（記録に必須の項目）を定義します。

具体的な記入例（架空の不具合対応シナリオでの記入イメージ）は [../example.md](../example.md) を参照してください。本テンプレートは記入すべき項目の構造のみを記載します。

## 利用方法
- **対象**: 全14段階の実施内容を記録（docs/skill-logs/ ログファイルに append-only で記入）
- **出力形式**: Markdown
- **記録基準**: 段階完了ごと、かつ重要な決定ポイント（ゲート条件）で記録
- **参照優先順位**: 本テンプレート > individual Phase logs

---

## ログファイル基本構成

```
docs/skill-logs/defect_repair_${CATEGORY}_${DATE}.md

例:
docs/skill-logs/defect_repair_DB_20260327.md
docs/skill-logs/defect_repair_IPC_20260325.md
```

### ファイル名規則
- `CATEGORY`: 不具合カテゴリ （DB / IPC / Performance / UI / BusinessLogic など）
- `DATE`: 対応開始日（YYYYMMDD）

### Append-Only 運用ルール
1. 新規対応開始時に新ファイル作成
2. 段階完了ごとに内容を **末尾に append**
3. 既存記録の削除・上書きは禁止
4. 誤記修正は「訂正: …」として新たにセクション追記

## ログファイルヘッダ（全対応共通）

```markdown
# 不具合対応ログ - [カテゴリ]（[YYYY-MM-DD]）

**ログファイル**: defect_repair_[CATEGORY]_[YYYYMMDD].md

## 基本情報

| 項目 | 内容 |
|------|------|
| **不具合ID** | [チケットID] |
| **タイトル** | [Module] Symptom（エラー内容、機能名） |
| **カテゴリ** | [DB系/IPC系/Performance/UI/BusinessLogic 等] |
| **報告日** | [YYYY-MM-DD] |
| **対応開始** | [YYYY-MM-DD HH:MM:SS +09:00] |
| **対応完了予定** | [YYYY-MM-DD HH:MM:SS +09:00] |
| **ステータス** | 進行中 → 完了 |

| **影響度** | [クリティカル/重大/軽微] |

---
```

## ログ整理のルール

### 追記時のルール（Append-Only）
1. **追記のみ** — 既存記録の削除・修正をしない
2. **タイムスタンプ付き** — 各セクションに「段階番号＋日時」を記載
3. **承認ステータス明示** —各ゲート時点で「未承認」「承認済」を明記

### 誤記発見時

```markdown
## 訂正: [対象段階] の[訂正対象項目]（[YYYY-MM-DD HH:MM:SS]）

**誤記**:
- 記載：[誤った内容]

**訂正**:
- 正確：[正しい内容]

**理由**: [訂正理由]
```

記入例は [../example.md](../example.md) の「誤記訂正の記入例」を参照。

## Checklist: ログファイル完成度確認

- [ ] ヘッダ情報（不具合ID、タイトル、対応者）が記載
- [ ] 14段階すべてが記載されている
- [ ] ゲート条件3か所（段階7, 11, 13）が明記されている
- [ ] 各段階で「承認ステータス」（未承認 / 承認済）が記載
- [ ] TRK（Tracking ID）が一貫性を持って追跡可能
- [ ] 変更ファイル・テスト結果が具体的に記載
- [ ] Append-only で改変・削除なし
- [ ] タイムスタンプが記載（日時の追跡可能）
- [ ] 最終レポート（Lessons Learned含）が記載
